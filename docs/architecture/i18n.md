# Multi-Lingual & Multi-Currency Native

> Status: skeleton — locale switcher, formatting helpers, Rust money/tax
> primitives, Supabase schema. Resource bundle loader + invoice rendering
> land in PR #6.

## Goals

- Every monetary amount displays in the active locale's preferred form
  (`Rp 16.000.000`, `€16.000,00`, `$16,000.00`, `¥16,000`).
- Tax labels follow the jurisdiction (`PPN 11%`, `MwSt. 19%`, `GST 9%`).
- FX rates and tax rules are versioned: a 2024 invoice rendered today
  must reproduce the rate that was in force at the time of the invoice.

## Components

### `crates/aether-money`

- `Money` — `(minor: i64, currency)` to avoid float drift.
  Operations: `add`, `mul_bps` (for tax application).
- `Currency` — ISO-4217 + minor-unit count (USD/EUR/GBP=2, JPY/IDR=0).
- `FxRate` — `(from, to, bp1e4, as_of)`. `bp1e4` is the multiplier ×
  1e8 stored as integer.
- `convert(amount, rate)` — handles minor-unit difference between source
  and target currency.
- `TaxRule` — jurisdiction (country + subdivision), scope
  (value-added/sales/withholding/excise), rate in bps, validity window.

### `packages/i18n`

- `LocaleProvider` + `useLocale()` — context-based active locale.
- `LOCALES` — supported descriptors (en-US, en-GB, id-ID, de-DE, ja-JP, zh-CN).
- `formatMoney`, `formatNumber`, `formatDate`, `formatRelative` — thin
  `Intl.*` wrappers.
- `useTranslation` — `t(key, params)`. Real bundle loader lands in PR #6;
  skeleton returns the key as-is.

### Supabase schema (`0006_localization.sql`)

- `currencies` — ISO-4217 dictionary
- `exchange_rates` — TimescaleDB hypertable with bp1e4 integer rate
- `tax_rules` — versioned per (country, subdivision, scope) + display
  string. Seeded with PPN 11%, German MwSt. 19%, UK VAT 20%, AU GST 10%,
  Japan 消費税 10%, Singapore GST 9%, US CA/NY sales tax.
- `tenant_locale` — per-tenant default locale + currency + timezone.

## UX

Top-bar chrome includes a `<select>` driven by `LOCALES`. Switching
locale rerenders the active shell with new formatters; chrome state
(IPC, Realtime) is preserved — same architecture as the Dynamic Shell
switcher.

## Rationale

- **Integer minor units**, not float: a single-cent rounding error per
  invoice across millions of invoices destroys reconciliation. Postgres
  `NUMERIC(18,4)` and Rust `i64` agree on intent.
- **Versioned tax rules**: tax authorities backfill amendments. We
  always render at the rate in force at `transaction.created_at`, never
  the latest rate.
- **FX as bp1e4**: same precision discipline; lossless round-trip.
